Start or resume the [shared task](../boi-domain-work/SKILL.md), preserving current source/meaning revisions. Use [source intake](../boi-source-intake/SKILL.md) only for changed or new bytes. Read [SVID semantic construction](references/semantics.md) before interpretation and [existing source adapters](../boi-source-intake/references/existing-contracts.md) when workbook context, scoped review or bounded repair is needed.

Read the current SVID profile, common descriptors, relation vocabulary, quantities and unit definitions that may fit the metadata. Compare existing meaning and scope before reuse or extension. Separate the source row, business property, equipment instance and physical observation. Preserve every row, description, correction, identity ambiguity and unknown field.

Build reusable component/property/procedure relationships with owned conditions and evidence. Names, numbers, AI/AO suffixes and source paths cannot decide role, equivalence, units or connectivity. Paths may be inferred. Use source-grounded interpretation and current contracts, not hardcoded parameter dictionaries or semantic regex routes.

Review typed core meanings and dependencies separately from unresolved descriptive claims. Add/repair descriptors and relationships through follow-up revisions, preserving prior interpretations and source quotes. Track represented records, qualified meanings, relationships and unresolved items. Verify that a fresh natural-language request discovers and uses them without the intake session or expected parameter pointers.

Formula previews need current parameter/unit authority, a typed plan and actual engine output. Missing data, stale observations and unknown units remain explicit. Metadata, reviews and generated Formulae do not establish a live catalog, current measurement or equipment-control authority.

When the selected published definition declares `calculation_context`, follow the [conditional definition and full source review contract](../../references/local-preparation.md). Preserve its interpretation status and every source uncertainty. Bind explicit scenario inputs to the same current definition, reviewed assumptions and exact model/module/location scope; missing or mismatched context remains unknown. State supplied development assumptions in the answer and distinguish them from actual observations.

For a server-registered database source, follow [DB intake and reuse](../../references/database-intake.md). Read actual rows as well as schema, reuse admitted Profiles, preserve source roles/conditions and complete publication before fresh-session answers. The installed DB adapter handles evidence conversion and resume; the agent supplies grounded meaning, not caller SQL or fabricated review.
