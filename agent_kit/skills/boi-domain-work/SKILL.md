Resolve the authenticated connection and current capabilities. A task reference resumes that exact server task: read status before requesting next work. Preserve package revisions, source membership, completed stages and pending/failed/unknown attempts. Do not reconstruct progress from conversation memory or create another task to evade a limit.

For assetization, use `boi_knowledge_work` with the request and actual source references. The server assigns scope from current identity. Follow [the installed task interface](../../references/host-work.md) and the returned versioned next-work schema. Read package instructions and existing knowledge, perform the external interpretation or declared operation, then submit its actual output and evidence references. A submitted result is not a newly executed result or proof that all work is complete.

Write each asset's short description about its subject, role, core meaning and applicable scope. Processing instructions and review status belong in their separate fields. Preserve source-grounded labels and aliases without inventing translations or identifier equivalence. Use existing evidence-bearing fields for role, quantity, unit, procedure, conditions and relations; read [metadata discovery and use](../../references/host-work.md#metadata-discovery-and-use) to connect those fields to subsequent retrieval and evaluation.

Discover process, SVID, DEXA and science packages with `boi_domain_packages`; select from their applicability and the material's meaning. Read the selected task's exact package revisions, including shared dependencies, using each returned `skill_path` and `resource_digests`. Follow reference links through that pinned closure. For a novel domain, use common source/claim/condition/evidence capabilities and record what needs new domain definitions. Follow [package authoring and qualification](../../references/package-operations.md) when reusable guidance needs an extension: fixed policy, ordinary proposal, independent evaluation, trial, adoption and monitoring. Preserve supported usable knowledge without forcing a known schema or implying unsupported execution.

For an ordinary question, use [description and language recovery](references/description-discovery.md) when lexical results miss the described target or use a different language. For an ordinary question, discover existing knowledge and applicable reviews, select core meanings with owned conditions, exceptions and counterevidence, then prepare and bind the native answer. Reuse saved answers when their question, scope, dependencies and data validity fit. Direct source supplementation remains distinct from reviewed meaning reuse. Use native query/Formula execution for requested data and calculations, retaining actual result references.

Deliver the answer, relevant limitations, readable source links and useful task/result links. Verify final meaning and protected source access. Read [existing native contracts](references/existing-contracts.md) only for the relevant answer, review, query, Formula or recovery operation. Transport failures require contract repair, not wholesale re-extraction or repeated unchanged model work. No schema, storage or model opinion establishes scientific truth, live equipment connectivity or production approval.

For a server-registered database source, follow [DB intake and reuse](../../references/database-intake.md). Read actual rows as well as schema, reuse admitted Profiles, preserve source roles/conditions and complete publication before fresh-session answers. The installed DB adapter handles evidence conversion and resume; the agent supplies grounded meaning, not caller SQL or fabricated review.
