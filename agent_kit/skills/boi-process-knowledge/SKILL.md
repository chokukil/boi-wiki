name: boi-process-knowledge
description: Build reusable process meanings, definitions, causal and conditional relationships, and evidence-backed answers using the existing BoI process contracts.
---

Use the [shared task](../boi-domain-work/SKILL.md) and [source intake](../boi-source-intake/SKILL.md) for new or changed material. Discover the current process profile, harness and existing definitions. Read [process semantic and review contracts](references/existing-contracts.md) before authoring or repairing meaning; retain their full evidence, scope and bounded-repair requirements.

Identify process records from the source; distinguish original descriptions, comparison answers and evaluation comments. Propose independently checkable terms and assertions for targets, purposes, actions, sequences, compositions, mechanisms and control quantities. Retain causal/conditional links, modality, applicability and exceptions. File order is not causality; a composition used by an operation is not thereby a method. Expand acronyms only when source evidence establishes the expansion.

For text-backed values requiring reviewed concept reuse, follow [scoped concept reuse](references/scoped-concept-reuse.md) and the current query schema. Keep original text facts and definition-review authority separate.

Compare existing concepts by meaning and scope. Reuse exact applicable revisions, reinforce with new evidence, and preserve conflicts or unresolved equivalence without applying the disputed definition. Attach operational conditions to the operation and definition-specific limits to the definition. Matching names do not establish identity; different application contexts alone do not establish different definitions.

Bind claims and relationships to exact original fields. Review represented meaning and substantive omissions against the whole applicable source, independently of structural checks. Repair affected nodes and dependencies within the retained budget; preserve stable IDs, previous revisions and unchanged judgments. Source-reported mechanisms remain reported until separately verified scientifically.

Make qualified concepts and relationships discoverable through current Wiki projections with source and history links. Verify reuse from a fresh task context without expected pointers: explanations must preserve requested meaning, conditions and uncertainty. Storage, reviewer acceptance and a valid binder remain separate from accurate final answers and source navigation.

When only an item's title or description needs correction, read the exact stored bound process asset and its original source. Use the shared task's `revise` change with that unchanged bound content, evidence and dependencies. The server accepts this preservation only under the process package and exact prior source/meaning match. Do not convert it back into a new extraction draft or rebuild bindings, partitions, review history or reusable IDs. Describe the actual processes, targets, purposes and distinguishing conditions; keep review status separate. A document containing several processes needs a description representing its actual scope, not a new duplicate definition for each search phrase.

After a metadata revision, follow `prior_review_discovery` from the meaning index when provided. It identifies an exact unchanged meaning/evidence lineage, not inherited approval. Read the original review's usable nodes and limitations, select its original meaning revisions, and let native preparation check current permissions and dependencies. Reuse those judgments when admission succeeds; do not create a replacement review merely to attach it to a new display revision. A saved answer's `current_reuse` read distinguishes exact metadata changes from changed meaning or evidence and retains its original citations. This read still does not assess a different question or new data.

For a server-registered database source, follow [DB intake and reuse](../../references/database-intake.md). Read actual rows as well as schema, reuse admitted Profiles, preserve source roles/conditions and complete publication before fresh-session answers. The installed DB adapter handles evidence conversion and resume; the agent supplies grounded meaning, not caller SQL or fabricated review.
