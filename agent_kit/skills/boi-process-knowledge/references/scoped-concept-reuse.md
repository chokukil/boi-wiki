# Reusing concepts behind original text values

Use the existing dictionary for discovery only. Related words, broader/narrower terms, acronyms and same-identity claims have different meanings. A shared label is not an approved relationship. Preserve the exact source text and the original typed predicate, polarity, modality, conditions, exceptions and declared time.

When multiple source expressions appear to refer to a reusable concept, first read their complete original fields and existing concept definitions. Separate source-declared naming facts from your scoped interpretation. Record unresolved ambiguity and conflicting roles rather than extending an equivalence claim.

The common meaning contract already provides MeaningConcept.reused_definition. For text-backed exact queries, read boi_knowledge_query(operation=schema). Its concept_reuse_declaration describes the source-address adapter stored under the existing KnowledgeContent.extensions.scoped_concept_reuse. Each link names the common concept and interpretation assertion, exact source revision/assertion pointer, unchanged predicate and literal. The target definition must contain exactly one unambiguous concept. Do not manufacture a source_reported naming assertion when the source does not state equality. This adapter is not ACTIVE-release approval or a replacement ontology.

Prepare source evidence and dependencies through the ordinary shared task/publication path. Bind interpretation prose and original evidence to each relation assertion. Keep source fact use contracts on the original source revisions; the relation definition grants none. Obtain the existing native definition review for the exact relation definition, reading its selected dependencies and original sources. A review of only source statements does not review the concept link. Preserve first failures, review limits and historical revisions.

For a later question, discover the relevant concept and scoped reuse definition through current search/catalog and read their meaning and review relationships. Use resolve_concepts with an authored source_query and exact selected definition/review/target references for the relevant filter indices. It reconstructs the literal comparisons only at the reviewed source addresses. Pass its returned query unchanged to the ordinary execute operation with the requested authorized population and a stable idempotency key. It cannot turn a top-k search into a complete set, transfer source qualifications, erase conditions, or interpret a different role.

The protected query retains the original query and exact reuse dependencies. New requests and result reads check current relation, target, review and source revisions and permissions. If a definition or source is corrected, reconcile that exact change and obtain a current applicable review; do not substitute a historical supported review. An unrelated addition should not require a new semantic judgment when the original selected-dependency scope is still current. Reading an old result is not executing the new question.

Verify source-based invariants before evaluating: a spelling-only change should preserve the exact scoped set; role, polarity, modality, target, conditions or time changes must retain their own semantics. New data outside the reviewed scope stays outside it until separately interpreted and reviewed. Do not add question phrases, special alias arrays, expected answers or regex routing to the engine.
